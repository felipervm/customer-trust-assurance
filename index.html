I was curious about a simple problem: what happens when an AI assistant keeps answering security questions after the policy behind those answers has changed?

I built a small, fictional security library and tested what an outdated response would look like—and what I would want to check before anyone sent it to a customer.

02 / WHAT I'D BUILD INTO THE WORKFLOW

Check the
source. Then
share the answer.

My takeaway isn't that every old answer is wrong. It's that even a true answer needs current evidence before it can be trusted as a security assurance statement.

01 / TRACE

Keep the evidence attached.

Save each answer with a policy ID, document version and owner. A plausible sentence without a traceable source should not be enough.

02 / FLAG

Make changes visible.

When a policy is updated, identify every answer that depends on it and queue it for review—even if the wording looks familiar.

03 / REVIEW

Leave judgment with people.

Use automation to find conflicts and gaps. Let the security owner decide what is appropriate to publish to customers.
